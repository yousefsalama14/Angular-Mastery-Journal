أنواع البيانات (Data Types)

let age = 25; let name = "Youssef"; let isStudent = true; console.log(typeof age, typeof name, typeof isStudent);
→number string boolean

typeof بيقولك نوع القيمة اللي جوه المتغير

النوعين الأساسيين: Primitive و Reference

أنواع البيانات في JS بتتقسم قسمين كبار، والفرق بينهم مهم جدًا وهنرجعله كتير:

string
"Youssef"
number
25, 3.14
boolean
true, false
undefined
undefined
null
null
symbol
Symbol()
bigint
123n

دول الـ 7 أنواع الـ Primitive (البسيطة). أي حاجة تانية غير كده — زي object, array, function — بتندرج تحت نوع واحد اسمه object وده الـ Reference type.

الفرق العملي بينهم: إيه اللي بيتنسخ؟

ده أهم فرق عملي هتشوفه في الشغل كل يوم:

Primitive: لما تنسخه، بتاخد نسخة مستقلة تمامًا

let a = 10; let b = a; b = 20; console.log(a, b);
→10 20

تغيير b مأثرش على a خالص، لأن كل واحد فيهم قيمته منفصلة

Reference (object/array): لما تنسخه، بتاخد "عنوان" مش القيمة نفسها

let obj1 = { age: 10 }; let obj2 = obj1; obj2.age = 20; console.log(obj1.age, obj2.age);
→20 20

obj1 اتغيرت هي كمان! لأن obj1 و obj2 بيشاورو على نفس المكان في الذاكرة، مش نسختين منفصلتين

هنرجع لها: النقطة دي بالظبط هي اللي بتفرق كتير في Angular لما نتكلم عن Change Detection وObjects — امتى Angular بيحس إن حاجة اتغيرت وامتى لأ.

legacy قصة undefined و null

الاتنين بيعبروا عن "مفيش قيمة"، بس مش نفس المعنى بالظبط:

الحالةالمعنى
undefinedالمتغير اتعرف بس محدش حط له قيمة لسه — JS نفسها بتحطها
nullإنت شخصيًا قررت إن "مفيش قيمة هنا"، بشكل متعمد
let city; console.log(city);
→undefined
مصيدة شهيرة في المقابلات: جرب typeof null هتلاقيها بترجع "object" مش "null". ده معروف إنه bug قديم في تصميم JS الأساسي من أول نسخة، وفضل موجود لحد دلوقتي عشان تصليحه ممكن يكسر مواقع قديمة كتير جدًا لو اتصلح.

Dynamic Typing — إيه اللي بيميز JS

في JS، نفس المتغير ممكن يحمل أنواع مختلفة في أوقات مختلفة، من غير ما تحدد النوع مقدمًا:

let value = 10; value = "hello"; value = true;
→JS مبتشتكيش، الاتنين شغالين

ده مختلف عن لغات زي Java أو C# اللي المتغير فيها بيتحدد نوعه من الأول ومينفعش يتغير. لما نوصل لـ TypeScript (اللي Angular مبني عليه)، هنرجع لنفس القدرة دي بس بشكل أكتر أمانًا.

مصيدة تانية: == مقابل ===

عشان JS بتحاول تكون "مرنة" في المقارنة، فيه فرق مهم بين عاملين:

console.log(5 == "5"); console.log(5 === "5");
→true
→false
العاملبيعمل إيه
==بيحاول يحوّل النوعين لنفس النوع الأول، وبعدين يقارن
===بيقارن القيمة والنوع مع بعض، من غير أي تحويل
القاعدة العملية: استخدم === دايمًا تقريبًا. الـ == بيسبب bugs غريبة وغير متوقعة، وده سبب رئيسي إن TypeScript بيمنع المقارنة الغلط دي من الأساس.

خلاصة: امتى تستخدم كل نوع

النوعتستخدمه لـ

booleanحالات true/false، شروط

سؤال مقابلة 1

"إيه الفرق بين == و ===؟" — سؤال أساسي في أي مقابلة JS مهما كان مستواها.

سؤال مقابلة 2

"إيه نتيجة typeof null وليه؟" — سؤال بيفرق بين اللي فاهم تفاصيل اللغة واللي حافظ بس.

سؤال مقابلة 3

"إيه الفرق بين Primitive و Reference types من ناحية الـ memory؟" — أساس لفهم مواضيع أعقد بعدين زي immutability.
