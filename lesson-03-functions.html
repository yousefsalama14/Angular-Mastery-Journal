الدوال (Functions)

كتلة كود معاها اسم، تقدر تناديها براحتك أي وقت وهي تنفذ نفس الشغل
function greet(name) { return "Hello, " + name; } console.log(greet("Youssef"));
→Hello, Youssef
بمنطق بسيط: الـ function زي آلة قهوة — بتاخد منك حاجة (اختياري)، بتشتغل عليها، وبترجعلك نتيجة. وإنت اللي تقرر تمسك النتيجة دي جوه متغير ولا تسيبها تروح في الهوا.

3 طرق تكتب بيها function

زي المتغيرات، فيه أكتر من طريقة تعرّف بيها دالة، وكل واحدة ليها استخدام مختلف:

1. Function Declaration — الطريقة التقليدية

function add(a, b) { return a + b; }

2. Function Expression — الدالة بتتخزن جوه متغير

const add = function(a, b) { return a + b; };

3. Arrow Function — الأحدث، شكل مختصر

const add = (a, b) => a + b;

بمنطق بسيط: التلاتة طرق بيعملوا نفس الحاجة بالظبط، الفرق بينهم بس في الشكل ووقت إنك تقدر تستخدمها بدري ولا لأ. في الشغل الحقيقي هتلاقي الناس بتستخدم Arrow Function في أغلب الوقت لأنها الأحدث والأقصر.

legacy الفرق العملي بين declaration و expression

الفرق مش بس شكلي، فيه فرق حقيقي في السلوك بسبب حاجة اسمها Hoisting (اللي اتكلمنا عنها في درس المتغيرات):

console.log(sayHi()); function sayHi() { return "Hi!"; }
→Hi!

اشتغلت! لأن Function Declaration بتترفع بالكامل لفوق الملف (اسمها ومحتواها)، فتقدر تناديها قبل ما توصل لسطرها فعليًا.

console.log(sayBye()); const sayBye = function() { return "Bye!"; };
→Uncaught ReferenceError: Cannot access 'sayBye' before initialization

فشلت! لأن sayBye هنا معرّفة بـ const، ومتغيرات const/let بتترفع بس بتفضل في Temporal Dead Zone لحد ما سطرها ييجي فعليًا.

new Arrow Functions — المشكلة اللي جت تحلها

Arrow functions اتضافت في ES6 (2015)، وهي مش بس اختصار شكلي. أهم فرق حقيقي بينها وبين function العادية هو التصرف مع this.

بمنطق بسيط: this زي كلمة "أنا" — مش بتقصد حاجة ثابتة، هي بتقصد "مين اللي بيتكلم دلوقتي". لما function عادية تتحط جوه function تانية، هي بتدخل "تتكلم بصوتها هي" فـ this بتتلخبط. أما arrow function معندهاش "أنا" خاصة بيها، فبتسيب الكلام لمين ما كان بيتكلم من الأول.

المشكلة قديمًا مع function العادية:

const user = { name: "Youssef", hobbies: ["coding", "reading"], printHobbies: function() { this.hobbies.forEach(function(hobby) { console.log(this.name + ": " + hobby); }); } }; user.printHobbies();
→TypeError: Cannot read properties of undefined (reading 'name')

داخل function العادية جوه forEach، الـ this اتغيّرت وما بقتش تشاور على user تاني.

الحل بـ Arrow Function:

const user = { name: "Youssef", hobbies: ["coding", "reading"], printHobbies: function() { this.hobbies.forEach((hobby) => { console.log(this.name + ": " + hobby); }); } }; user.printHobbies();
→Youssef: coding
→Youssef: reading

Arrow function معندهاش this خاص بيها، فبتستخدم this بتاع الكود اللي حواليها. المشكلة اتحلت من جذورها.

ليه ده مهم في Angular: هتشوف arrow functions في كل حتة تقريبًا جوه Components وServices، خصوصًا في callbacks وsubscriptions، بالظبط عشان مشكلة الـ this دي.

Parameters و Default Values

تقدر تدي parameter قيمة افتراضية لو محدش بعتها:

function greet(name = "friend") { return "Hello, " + name; } console.log(greet()); console.log(greet("Ahmed"));
→Hello, friend
→Hello, Ahmed

دي إضافة من ES6 كمان. قديمًا كان لازم تتحقق يدويًا جوه الدالة لو الـ parameter مش موجود.

Callback Functions — دالة بتتبعت لدالة تانية

مفهوم أساسي هتقابله كتير جدًا: دالة تقدر تستقبل دالة تانية كـ parameter، وتناديها هي بنفسها في الوقت المناسب:

function processOrder(orderName, onDone) { console.log("Preparing: " + orderName); onDone(); } processOrder("Coffee", () => { console.log("Done!"); });
→Preparing: Coffee
→Done!

الـ arrow function اللي بعتناها هنا اسمها callback. المفهوم ده أساس فهم Promises، async/await، و Event handling في Angular لاحقًا.
